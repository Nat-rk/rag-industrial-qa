# RAG QA 系统验收报告

> 对象：本项目（方案 A = BM25 + Rerank，方案 B = Hybrid + Rerank）
> 语料：`apply.pdf`，278 个父块 / 1679 个句子单元（沿用前几轮已验收的数据，未重建）
> 测试：15 题 × 2 种策略 = 30 次完整问答，全部真实调用智谱 API
> 数据：`_local/results/qa_results_v3.json`（最新一轮；含引用越界检查与机械生成的来源表）
> 日期：2026-11-11

## 0. 一句话结论

**两条链路都能跑通，都能给出带页码出处的中文答案，并在资料不足时拒答。**
30 次问答 0 失败 0 降级；12 道有答案的题**检索命中 12/12**、**引用命中 11/12**；3 道资料不足的题 6 次全部拒答且无编造。

唯一未命中的引用是 Q20：答案数值正确，但两张不同应用场景的表数值逐字相同，模型引用了 p49（Table 19，现场总线场景），而不是权威页 p40（Table 13，数字量 I/O 场景）。**检索命中了，引用没有落到最直接的那张表。**

两种策略的差别不在"对不对"，而在"答得全不全、快不快"：Hybrid 的平均回答更完整，代价是每次多约 13 秒（24.3s → 37.3s）。

## 2. 一次问答到底做了什么（Q04 实测）

问题：`Which parameter selects Positioning or Synchronization mode, and what are the corresponding option values?`

| 步 | 动作 | 实测结果 |
|---|---|---|
| 1 选策略 | `build_retriever(mode)` | bm25 → 只建 BM25；hybrid → Dense + BM25 + RRF |
| 2 召回句子 | `retriever.retrieve(question, 30)` | 30 个句子单元（带 parent_id、分数） |
| 3 回填父块 | `adaptive_backfill(...)` | 按 parent_id 去重；不足目标数就扩到 60/120/240 |
| 4 rerank | `rerank_candidates(question, 30, 10)` | rerank-pro 一次调用，30 → 10 |
| 5 上下文 | `build_context(picked)` | 10 个块，每块带 `[Source n] / File / Page / Parent ID / Section` |
| 6 生成 | `llm_answer(question, context)` | glm-4.5-flash，单题 10–80 秒（随答案长度与策略变化） |
| 7 引用 | `build_citations(answer, sources)` | 从答案里抽 `[Source n]` → 文件名 + 页码；越界编号会被标出 |
| 8 打印 | `show(result)` | 见下方真实输出 |

v3 的 bm25 模式实测：交付 10 个父块，答案 1 段、引用 2 条（p8、p16），端到端 22.6 秒。

最终答案（v3，bm25）：

> 参数 1-00 Configuration Mode 用于选择定位或同步模式，对应选项值为 [9] Positioning 和 [10] Synchronization [Source 2]。此外，该参数还提供其他同步模式选项，如 [11] Cyclic Sync. Position 和 [12] Cyclic Sync. Velocity [Source 4]。

来源表由 `citation.py` 机械生成：

> 参考来源：[Source 2] apply.pdf 第 8 页；[Source 4] apply.pdf 第 16 页

答案里的两个页码都是真的，点得回原文；p16 提到的 [11]/[12] 也确实写在手册里，只是超出了题目期望。

## 3. 两种策略共用什么、差什么

| 环节 | 方案 A（bm25） | 方案 B（hybrid） | 是否共用 |
|---|---|---|---|
| 句子召回 | BM25 首轮 30 句（45 停用词） | Dense 50 句 + BM25 50 句 → RRF(k=60) → 取前 30 句 | 否，只差这一处 |
| 父块回填 | 自适应 30→60→120→240 | 同左 | **是** |
| Rerank | rerank-pro，30→10 | 同左 | **是** |
| 上下文构建 | `context_builder` | 同左 | **是** |
| LLM 生成 | glm-4.5-flash | 同左 | **是** |
| 引用整理 | `citation` | 同左 | **是** |

切换方式只有一行：`config.py` 的 `RETRIEVAL_MODE = "bm25"` 或 `"hybrid"`；
命令行也可以临时覆盖：`python main.py "问题" hybrid`。

## 4. 30 次验收汇总（v3）

```
策略     有答案题 检索命中  有答案题 引用命中  资料不足 拒答  平均交付  引用总条数  降级  生成失败  平均耗时
bm25     12/12            11/12             3/3           10.0      16         0     0        24.3s
hybrid   12/12            11/12             3/3           10.0      15         0     0        37.3s
```

口径说明：

- **检索命中**：12 道"有答案"的题，交付的 10 个父块中是否包含权威页（`qa_cases.json` 的 `pages`）。这只看"有没有找到"，不看答案。
- **引用命中**：答案里标出的 `[Source n]` 对应的页码，是否至少有一个落在权威页上。**检索命中不等于引用命中**——Q20 就是检索命中、引用未命中。
- **拒答**：3 道"资料不足"的题，回答是否明确说"文档中没有足够信息"，且引用列表为空。
- **平均交付**：每题最终交给 LLM 的父块数量（目标 10）。
- **引用总条数**：按去重后的页码计，不是 `[Source n]` 标记的出现次数。
- **平均耗时**：单题端到端时间（检索 + 回填 + rerank + LLM），15 题算术平均，不含首次加载与建索引。
- **降级**：rerank 调用失败、退回原始顺序的次数（本次 0）；**生成失败**：LLM 调用失败后走兜底文案的次数（本次 0）。

## 6. 两模式的真实差异

| 维度 | bm25 + rerank | hybrid + rerank | 说明 |
|---|---|---|---|
| 答案正确率 | 12/12 | 12/12 | 这 15 题上没有差别 |
| 答案完整度 | 较简洁 | 更完整 | Q19 分场景列出 500 mm / 90°；Q04 反而更克制（只给 [9]/[10]） |
| 引用宽度 | 较克制 | 更克制 | 引用总条数 16 vs 15（上一轮是 59）；Q10 bm25 一次引 4 个来源，是最宽的一题 |
| 平均耗时 | 24.3 s | 37.3 s | hybrid 多一次 embedding 调用 + 融合计算 |
| 交付数量 | 10.0 | 10.0 | 都稳定交满 10 个父块 |

一句话：**这份英文语料上，加向量召回没有让答案更"对"，但让答案在"多父块/多场景"题上更完整；代价是每次多约 13 秒。**

## 7. 已知问题与限制

### 本轮已解决

- **M1 引用过宽（已解决）**：上一轮一个事实引 5–6 个同值页；本轮 Prompt 改为"只引最直接证据"，并在解析前截断模型自带的末尾清单、来源表由代码生成。30 次总引用从 59 条降到 31 条，Q26 收敛到 1 条。
- **S1 冲突题格式（已解决）**：Q19 现在按应用场景分条列出（线性 500 mm / 旋转 90°），各自带引用。
- **S2 来源格式不统一（已解决）**：答案正文只允许行内 `[Source n]`，末尾来源表由 `format_citations()` 机械生成，页码不会丢。
- **S3 降级未演练（已解决）**：`eval/test_rerank_failure.py` 注入连接异常、超时、500、429、空响应 5 类故障 × 2 策略 + 2 次正常对照，12/12 通过（降级后保序、页码映射正确、问答不中断）。

### 仍然存在

- **M2 无答案时仍然花满额**：拒答题也走完 30 句 → rerank → LLM，本次 3 题耗时 17–53 秒。可加轻量判据先判"疑似无答案"，但 rerank 分数跨题不可比，只能用同题内的相对值。
- **Q20 相似表竞争**：数值相同的不同场景表，rerank 分不开（0.9985 对 0.9996），引用落在 p49。答案本身正确，但读者拿到的不是最直接的那张表。已试过"按章节标题匹配场景"的 Prompt 规则，两模式仍选 p49，规则已回滚。
- **答案质量只做了单标注者人工核对**，15 题规模小，不能当泛化证据。

### 暂时不必处理（N）

- N1 多轮对话、会话记忆——本阶段明确不做。
- N2 多文档扩展——元数据已带 `file_name`，扩展时不用改结构。
- N3 自动路由（按问题选 bm25/hybrid）——目前手动切换足够。
- N4 答案质量自动评分（RAGAS 等）——15 题人工核对更可靠。

## 9. 结论

1. 系统已经能回答"文档里能查到"的问题，并在查不到时明确拒答——这是本阶段的核心目标，已达到；引用命中 11/12，唯一缺口是相似表的场景归属。
2. 两种策略共用 5 个下游模块，切换只改一个常量，符合"不重复实现两套问答系统"的要求。
3. 本轮把"引用过宽"从 59 条压到 31 条，代价是 Q10 这类题模型会一次引多个来源；**引用数量不是越少越好，能否落到最直接证据才是标准**。
4. 是否默认用 Hybrid：**在这份英文语料上，Hybrid 的优势是"更全"而不是"更准"，代价约 13 秒/次。**如果最终用户用中文提问，BM25 会因英文倒排几乎失效，那时 Hybrid 不是"更好"而是"必需"。
